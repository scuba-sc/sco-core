## sdk-v2.0.0 (2026-10-12)

The plugin ABI remains 1.1, unchanged. The SDK major version reflects breaking packaging/profile and release-process changes: separate core and game extension archives, an independently buildable core-source kit, and build-once promotion requiring a signed, hash-bound maintainer approval.

The prepared sdk-v1.2.0 was never published; its entries are folded into this release below.

- **Windows extracted-SDK verification:** the archive-test job checks out the packaging verifier and its complete manifest inputs, rather than only the shell runner. The verifier reads evaluated MSBuild toolchain include paths so Windows SDK/CRT headers are recognized without relying on the shell's `INCLUDE`. Builds remain confined to extracted SDK headers, with compiler-resolved checkout leakage refused.

- **Extracted SDK storage and public-header proof:** storage resolves host-owned directory aliases before SQLite opens the database, fixing macOS temporary-root failures without permitting database-file symlinks. External C/C++ examples now compile with exact compiler-resolved installed public-header membership checks; hidden checkout and unshipped nested dependencies are refused. Packaging also refuses recognized private-key and GitHub credential shapes before writing an archive. No plugin ABI change.

- **Optional ImGui coupling is host-specific, not the frozen C ABI:** document the exact source/configuration match and public-header hashes, drawing-plugin rebuild requirements and absence of cross-version raw-context compatibility; non-drawing plugins do not require ImGui.
- **Native trust and Lua reload limits:** native plugins are trusted in-process code, not a sandbox or a native-fault recovery guarantee; supported cached-table, worker and shutdown usage is explicit. Real-loader Lua tests cover repeated reload resource/callback cleanup, transaction rollback, persistent data, preserved budgets and optional read-only game-adapter boundaries. No runtime or ABI change.
- **Real-host SDK conformance:** independent native C consumers execute inspector, owned-NPC and actor-death contract fixtures through the neutral loader and host API; negative cases cover service absence/version/partial tails, ownership, wrong-thread raw calls, queued-work cancellation, and restart-required native provider refusal/fault retention. Engine responses are synthetic, not gameplay or native-process recovery certification.
- **SDK discovery acceptance:** conventional Copilot/IDE integration docs include an explicit read-only tool allowlist; static language views and real-browser search/keyboard checks cover the reference site, with deterministic cold-Pagefind readiness before shortcut focus checks, and local snapshot tooling binds catalogue/examples to exact source and archive inputs without approval, signing or deployment.
- **Language-route evidence:** catalogue mappings require language-specific tests; C/C++ and Lua actor/entity fixtures reject partial/null methods, C# wrappers clear failed-reopen state, and docs distinguish Windows x64 NativeAOT/host evidence from synthetic game-contract tests and unsupported routes. The C ABI is unchanged.

- **Strict neutral source SDK and macOS ARM64 development builds:** the `core-source` archive excludes game ABI headers, layout pins, examples and game-only test fragments, while retaining generic scanner/hook/host coverage. Packaging tests build and run every neutral CTest from an empty extraction and resolve external example includes to exact shipped public headers. VFS snapshots work on C++20 libraries without atomic shared-pointer specialization; ARM64 detours remain explicitly unsupported. The plugin ABI is unchanged.
- **Local SDK discovery:** `tools/sco-core-mcp/` adds a stdlib, read-only MCP stdio server with six catalogue tools, bounded example reads and source provenance; development aid only, with no SDK execution or game access.

- **Static SDK documentation:** a catalogue-backed site with local search builds as a read-only CI artifact for pull requests; trusted `main` pushes and manual dispatches deploy the validated site to GitHub Pages; project-authored site sources and dependency licence metadata are recorded, and the site is excluded from every SDK package profile.
- **Release promotion refusal coverage:** candidate, mandatory-check and draft round-trip logic now lives in testable stdlib tooling; signed negative tests cover the release refusal matrix and reject checkout-local signer policies.
- **Machine-readable SDK contracts:** `sdk/contracts/` records all 117 table methods and three native entrypoints, with compiler-validated signatures/extents, language evidence and explicit unspecified semantics; `tools/sdk_catalogue.py` builds a deterministic versioned JSON catalogue, and CI rejects inventory, documentation and support-claim drift.

- **Signed release manifests:** `tools/release_verify.py` binds publication approval to exact payload hashes, source and recursive dependency commits, builder identity and a maintainer SSH signature; negative tests cover tampering and fail-closed refusals.

- **Faulted native providers are restart-required, not recovered.** Attributed faults withdraw lookup and host scheduling; handed-out providers retain their state and mapped code without unload or resource release hooks. Logs, plugin reports and reload refusal tell the player to restart the game. Off-thread faults outside a host guard remain uncontained; cached tables and native process integrity are not guaranteed. No plugin ABI change.
- **Service-table unload admission is atomic across lifecycle paths:** a single loader gate blocks new queries before teardown, protects built-in provider state, retains backing state after a queried failed load, and reserves the entire dependent reload cascade before any member changes. Command, UI and host API reload routes share this gate; the plugin ABI is unchanged.

- **SDK releases build once and promote verified bytes:** a manual candidate workflow packages all four SDK profiles with SBOMs and provenance; tag publication requires a signed, hash-bound approval, downloads exact artifact IDs, and re-verifies a complete draft before making it public.

- **Direct native unload now respects service-table lifetime**, matching `UnloadOne`, app reload and `sco.reload`: `UnloadNative` refuses a native whose table was handed out before its unload export or owner release runs. Shutdown still tears it down while keeping its module mapped. The [lifetime audit](docs/design/service-table-lifetime.md) inventories built-in tables, accessors and lifecycle paths, and separates administrative refusal from fault/withdrawal/shutdown behavior. `TestServices` proves refusal through both public unload routes and retained shutdown pinning; `sco_api.h` and all table layouts are unchanged.
- **Service contracts and a kernel source SDK.** The [contract catalogue](docs/contracts.md) inventories the 117 public table methods and three plugin entrypoints, with buffer/tail rules, ownership, thread/reentrancy, failures, capability absence and cleanup; unestablished guarantees are explicitly unspecified. `sdk/package.py --profile core-source` produces an independently buildable kernel source kit, without game implementation, and `sdk/test-zip.sh` builds it from an empty extraction with `SCO_GAME_SC=OFF`. The kernel-only CI dependency gate now consumes the generated CMake target graph, compile commands, compiler depfiles and object/link inputs, with negative tests; symbol scans remain supplementary. The frozen 1.1 header is included and hash-checked for offline source builds. No ABI or gameplay behavior change.

- **Discovery refuses a plugin folder whose id belongs to a built-in, and says why** (`sco_api.h` unchanged; [plugins](docs/plugins.md#discovery)). A folder — native, Lua or data pack — whose `id` is one of the host's built-ins (`opts.builtins`, filled by `sco::app::Start` from `Platform::builtins`) is refused at discovery, before the api and entry checks and before any plugin code runs, with `refused: id 'teleport' belongs to a built-in plugin`: the log line and the plugin's `reason` (so `status` and `sco-plugin-check` show it) both name the id, instead of the old unclear `refused teleport: host passed no api or owner` that a data pack never got at all. The conflict is checked before `entry 'x' not found`, so a folder that may not load never has its entry opened. A **disabled** folder is not loaded, so it stays `disabled` and appends the same reason to `disabled file`. Ids are `[a-z0-9_]` on both sides, so the match is exact and case needs no folding. `requires` resolution is unchanged: a built-in still provides by its id. Tests: `tests/test_plugins.cpp` `TestDiscover` (native, Lua, data, disabled, missing-entry, a non-conflicting id still ready, the status line and the log) and `tests/test_app.cpp` `TestBuiltinIdConflict` (the same through `sco::app::Start`, with the built-in itself still loaded and working).
- **The plugin ABI 1.1 is frozen, with a golden and an old-binary test** (`sco_api.h` unchanged; no behavior change). `tools/abi_snapshot.py` compiles a probe against `include/sco_api.h` and compares its `sizeof` / `_Alignof` / `offsetof` / enum / macro output — the 128-byte `sco_api` table with every field offset and the function pointer order, every public struct, every result code, both version macros, the reserved padding — with the new `tests/abi/sco_api-v1.1.golden`, and checks that the header as released at tag `sdk-v1.1.0` still hashes to the sha256 the golden records. The pin is the semantic surface, not the bytes: `sco_api.h`'s comments have changed since that release (its licence note), its declarations have not. **The tool has no auto-update mode**: a difference prints the diff and fails, and a deliberate 1.x addition hand-edits the golden in the same PR — which is what catches a PR that edits `tests/abi_v1.c` and the header together. The second half is `tests/fixtures/plugins/native/frozen_v11_plugin.c`, compiled at test time against the header *extracted from the tag* (no binary is committed) and loaded by `test_plugins`: it must load, take a tick through `subscribe`, answer its command and unload once, so a change that breaks a 1.1 plugin fails even where the pins still match. Run by `tools/test.sh`, `tools/test-win.sh` and CTest `abi_freeze` in every job, kernel-only included. Docs: [Plugin API v1 § ABI freeze](docs/api-v1.md#abi-freeze), [CONTRIBUTING.md](CONTRIBUTING.md).
- **Kernel-only builds leave out `test_death_events`.** It includes `sc_game_events.h` and `src/game/services/death_events.h`, so it now builds only with `SCO_GAME_SC=ON`; the `kernel-only` CI job also fails if any object in a kernel-only build was compiled from game pack implementation code under `src/game` or `src/datacore` (from the compiler depfiles).
- **The release approval record is JSON, validated against a JSON Schema** (release hardening Gate G). `tools/ip_audit.py release --approval docs/legal/release-decisions/<tag>.json --tag <tag>` replaces the Markdown parser: the record is checked against the new `docs/legal/release-approval.schema.json` (JSON Schema draft 2020-12, validated in the standard library — no `jsonschema` in CI), then its semantics: the decision is `approve` and `distribution.status` `approved-for-publication`, `approved_at` precedes `expires_at` and nothing has expired (record or exception), `release_tag` equals the tag, `source.commit` is the tagged commit or an ancestor with only release decisions changed since, `profiles` covers every artifact role, artifact names are unique, and the optional `--artifacts DIR` is exactly the listed set (bytes and sha256). The old parser accepted a record with no artifacts, a malformed commit, an empty approver, a `approve-ish` decision and an expired approval; those are now refused with their reason. The record is not yet signed: `approver.key_fingerprint` is recorded, no signature is verified. `tools/test_ip_audit.py`: 48 tests, 35 of them synthetic defects each refused. `release.yml` passes `--tag $GITHUB_REF_NAME`. [Release checklist](docs/legal/release-checklist.md).
- **SDK packaging hardening** (strict manifest closure, per-archive metadata, archive limits). `sdk/package.py` now refuses a manifest whose components carry an unknown key, whose two profiles' components share one destination inside a profile's closure (legacy = core + game-sc), or whose `includes`/`requires` form a cycle, each with a test in `sdk/test_package.py`. The Star Citizen extension zip keeps its own `VERSIONS.txt.game-sc` and `SHA256SUMS.game-sc`, so unpacking it over the core SDK overwrites nothing (`sdk/test-zip.sh` asserts no file of the extension touches a core file, metadata included; `LICENSE`, the one file both zips ship, must be byte-identical). `tools/ip_audit.py zip` now also refuses unsafe paths (`..`, absolute, backslashes, drive letters, NTFS streams), Windows reserved names (`CON`, `nul.log`, `com1`, `LPT9.txt`), trailing dot/space segments, case-fold twins, duplicate entry names, nested archives, symlinks, and archives past the entry-count, per-entry, total-size or compression limits (464 entries, 1,707,380 bytes per entry, 5,338,552 bytes in total, 33:1 — four times what the legacy zip holds); every limit is boundary-tested (exactly at it passes, one past it fails, and a lying size header is refused on a bounded read before anything is unpacked).
- **Kernel: a native provider whose service was handed out can no longer be reloaded or unloaded mid-session** (`sco_api.h` unchanged; [plugins](docs/plugins.md#hot-reload), [API v1](docs/api-v1.md#host-commands), [service safety](docs/design/service-safety.md)). `sco::app::Reload` and the host command `sco.reload` refuse a native plugin whose service table `query_service` handed out — to another plugin or to the host — before anything of it is torn down: `FAILED` with `provides a service in use; restart the game to reload it`, `sco_plugin_unload` and `Release` never run, its services keep resolving and a table a caller held keeps working. Only a restart of the game reloads such a plugin; Lua plugins (which cannot provide services) and natives nobody ever asked a service of reload exactly as before. One predicate, `plugins::CanUnload(p, &why)`, is asked by every mid-session path (`Reload`, `UnloadOne`); `UnloadAll` — host shutdown, `sco::app::Stop` — still tears everything down in reverse load order as before and keeps a handed-out provider's module mapped until the process ends. `docs/design/service-safety.md`'s 128 -> 136-byte `guard_call` proposal is marked superseded for 1.x: the table stays 128 bytes and `tests/abi_v1.c` is unchanged — lifetime is handled by the refusal, not by growing the ABI. Tests: `test_app`'s pinned-provider case now asserts the refusal (`unload()` not run, the same table still resolving, `sco.reload` surfacing the why, the consumer still working, and `Stop` still unloading the provider); the Lua, native, busy and refusal cases are unchanged.

## sdk-v1.1.0 (2026-10-09)

The first SDK release. The plugin ABI is version 1.1 and stable from here on: version 1 only grows at the end of structs, so plugins built with this SDK keep loading in later 1.x hosts.
