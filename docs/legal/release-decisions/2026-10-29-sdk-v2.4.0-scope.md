# SDK 2.4.0 scope: native backends K-39 to K-42 in the release line

- Decision: **Recorded.** Fold the four native backend rows K-39 to K-42 into the `sdk-v2.4.0`
  release line, and treat the published `sdk-v2.4.0-rc.2` tag as a milestone on the way to that
  release rather than the release line itself.
- Decided by: scubamount (maintainer)
- Date: 2026-10-29
- Applies to: sdk-v2.4.0 preparation only
- Reviewed source: none; at `main` `0c977d3` none of the four rows has a native backend, so this
  record selects scope and states gates, not shipped bytes
- Supersedes: the sequencing half of the 2026-10-21 ruling — "2.4.0 ships all four fail-closed
  (contracts + synthetic providers only); native grounding is the first post-2.4.0 track
  (K-39..K-42)". This record changes **when** the native rows land in the release line, not
  **how** they behave; every rule in [Rules that still bind](#rules-that-still-bind) is unchanged.

**This record does not itself dispatch a candidate, create an approval record, sign, tag or
publish.** Those steps, and the site publication that follows them, remain the maintainer's.

## What `sdk-v2.4.0-rc.2` is

`sdk-v2.4.0-rc.2` is a published milestone at commit `844e136`, released 2026-10-28. It remains
published, immutable and valid as a milestone: consumers that pin it keep working, and it is not
re-cut, moved or deleted. It is not the release line, and the final `sdk-v2.4.0` tag is not
required to match its tree.

Two consequences follow, and both are scope statements only:

1. Work that lands after `844e136` can still be part of `sdk-v2.4.0`; the final tag is cut from
   whatever `main` the maintainer approves, not from the rc.2 commit.
2. Release notes and the `sco-release-scope` block must describe the final tag's contents, and must
   not present rc.2's contents as the release. rc.2's own notes stay as published.

## Rows moved into scope

The contracts for all four rows are already on `main`. What is missing is the native backend, and
in each case the capability is default OFF today with that absence stated in
[`docs/game/status.md`](../../game/status.md).

| Row | Capability | Contract on `main` | State on `main` `0c977d3` | Gate for the final tag |
|---|---|---|---|---|
| K-39 | `game.audio.play_once` | `sc_audio.h` 1.1 | OFF — "No native backend ships; held until current game-object registration can be confirmed at submission" | A read-only registration witness for a posted event on an unregistered object, or the row ships recorded as unproven and OFF |
| K-40 | `game.gamerules.read` | `sc_gamerules.h` 1.1 (`list_params` already ON) | OFF — "default production backend binds nothing (read returns UNAVAILABLE)" | A read-only receiver/route for the params blob with a host-owned change counter and no shifted fields, or the row ships recorded as unproven and OFF |
| K-41 | `game.entities.lookup` | `sc_entities.h` 1.2 | OFF — "no native adapter" | Owner-safe lifetime for the registry receiver and the returned class record through the copy, with a point-lookup seam distinct from the catalogue snapshot, or the row ships recorded as unproven and OFF |
| K-42 | `game.world.raycast_filtered` | `sc_world_control.h` 1.1 | OFF — "Synthetic policy only; no verified offline engine adapter" | A grounded single-hit contract (zone/world/grid references, skip-request lifetime, copied hit layout) with a process-lifetime fault latch, or the row ships recorded as unproven and OFF |

A row that reaches the final tag without a witness is still in scope: it ships the contract, the
synthetic provider and the refusal path, exactly as it does today, and its `status.md` row says so.
Scope here means "decided in this release line", never "enabled".

## Rules that still bind

1. **Fail-closed.** A capability reaches `ON` only after a read-only witness is proven on the
   verified build, and turning it on is a separate maintainer act. Nothing in this record enables
   a capability, and no row may be enabled to make a release gate pass.
2. **`GetPosition` stays rejected as an audio witness** (ruling 2026-10-21). K-39's witness is the
   audio pump's handling of a posted event for an unregistered object, not a position read.
3. **Fault latch.** Any native call that can fault carries an SEH and/or process-lifetime latch and
   returns `UNAVAILABLE`; a partial result is never returned and a latched row stays refused until
   process restart.
4. **No in-game claim.** Nothing here asserts game execution. Native rows are exercised on the
   verified build out of game; in-game acceptance remains the owner's V-row act.
5. **Default OFF stays the default** for every row above, including after it lands.
