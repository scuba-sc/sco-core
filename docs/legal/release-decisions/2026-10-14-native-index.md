# Engine-native index: publication channel

- Decision: publish the engine-native index on the documentation site and through the static MCP
  server, limited to row names, subsystem, tier and readiness; ship it in no SDK zip
- Decided by: scubamount (maintainer)
- Date: 2026-10-14
- Applies to: the engine-native index (`sdk/native_index.json` and its renderings) from SDK 2.2.0
  preparation onward
- Source basis: `sdk/native_index.json` as generated by `tools/native_index.py` on the 2.2.0
  candidate branch (316 rows); approved by the maintainer as written on 2026-10-14, against
  `sdk/native_index.json` on `main` at `b97fca6be471edd4a47988c21ae10377b0095902`
- Counsel review: not recorded

## Decision

The maintainer decided on 2026-10-14 that the engine-native index may be published through two
channels only:

1. the project documentation site, and
2. the static, read-only MCP server (`tools/sco-core-mcp`).

What a published row says is limited to the row name, its subsystem, its tier and its readiness.
Byte patterns, offsets, addresses and any other value that locates code or data in a game binary
are not part of the published index, in either channel.

The index ships in no SDK archive. No profile in `sdk/components.json` (`core`, `game-sc`,
`legacy`, `core-source`, `host-source-sc`) includes it, and no profile may be changed to include
it without a new maintainer decision.

## What landed on the candidate branch

- `sdk/native_index.json` is generated from the signature tables in `src/game/*_sigs.cpp` by
  `tools/native_index.py`; `tools/native_index.py --check` runs in `test.yml`. The file is
  classified in `excluded` in `sdk/components.json`, so it is in no SDK profile.
- The documentation site renders it at `/natives/`, inside the "Native & service reference" hub,
  and serves a byte-identical copy as `native-index.json`. The site generator refuses an index
  with unknown keys, an address-shaped or lowercase hash, a tier outside 1-4 or a source outside
  `src/game/`.
- The discovery MCP server reads the same file through `list_engine_natives` and
  `get_engine_native`. Both are opt-in (`--extended-tools`); the default tool list is unchanged.

## Conformance question for the maintainer

Every entry carries `id` (the row name), `subsystem` and `tier`; 48 of the 316 entries also carry
`capability`, the registry capabilities behind a tier-1 or tier-3 row. Readiness is expressed
by the tier and its capability list. Two further fields are present in every entry:

- `hash`: `_0x` followed by the first 16 hexadecimal digits of SHA-256 over
  `sco-core:native:<row name>`. It is derived from the row name only and is not an address,
  offset or pattern; the site test asserts that every `0x` run on the page is one of these hashes.
- `source`: the repository path of the `src/game/*_sigs.cpp` file that defines the row.

Neither is a byte pattern, offset or address. Whether these two fields fall within "row names,
subsystem, tier and readiness" is for the maintainer to confirm; this record does not decide it.
If they do not, the generator, the site page and the MCP tools must drop them before the site is
deployed from a commit that contains the index.

## What this record does not do

- It supplies no licence grant and no legal opinion. Counsel review is not recorded.
- It does not change the [game implementation export hold](2026-10-12-game-implementation.md) or
  the signature-row sources under `src/game/`; publishing a row's name does not publish the row.
- It approves no SDK scope, candidate, tag or release. SDK 2.2.0 scope is a separate, pending
  [draft](2026-10-14-sdk-v2.2.0-scope.md).
- It states no in-game verification. Tiers describe engineering evidence as recorded in
  `sdk/status_registry.json`, not gameplay acceptance; no entry is marked verified in game.
