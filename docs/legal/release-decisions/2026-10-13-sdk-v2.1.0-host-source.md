The maintainer selected "Fix kit licences first, then ask me", then "Fix kit build
first", and finally "Include in 2.1.0" after local archive and extracted-build
verification. The candidate scope is `core`, `game-sc`, `legacy`, `core-source`,
and `host-source-sc`. SDK version 2.1.0, game-pack version 0.4.0, and plugin ABI
1.1 remain unchanged.

For this candidate only, host-source inclusion supersedes the exclusion in
[the four-profile scope decision](2026-10-12-sdk-v2.1.0-scope.md) and the
[implementation export hold](2026-10-12-game-implementation.md) to the extent
needed to distribute the exact `host-source-sc` archive. It does not authorize
product releases, other implementation exports, site publication, new licence
grants, or any change to the published SDK 2.0.0 decision or bytes.

The source kit retains repository layout, private host headers, existing
provenance, dependency notices, SPDX records, and checksums. Host headers remain
non-public plugin API. Added game headers and synthetic fixtures belong to the
host source kit, not the neutral source kit. Existing origin and licence records
are preserved; passing an archive audit is not a legal opinion.

## Evidence and release sequence

The local corrected archive contains 625 files and passes archive structure,
exact manifest selection, checksums, embedded SBOM, attribution inventory,
provenance, artifact refusals, and licence/notices checks. The local extracted
host build passes five synthetic host fixtures. This is not native Windows or
gameplay acceptance.

The changes must be reviewed and merged to `main`. Mandatory checks must pass on
that exact source SHA, including the extracted host archive on Linux and MSVC.
Only then can `release-candidate.yml` produce the expanded immutable payload:
five archives, five SBOM sidecars, and `SHA256SUMS`.

The old nine-file candidate and its unsigned approval are historical evidence,
not approval for the new eleven-file payload. Generate a fresh schema-v2 approval
from the new run and artifact IDs, exact source/dependency SHAs, component
manifest digest, sizes, and hashes. Re-download and verify every payload byte
before the maintainer signs, commits the detached signature, tags, and publishes.
No run IDs, artifact IDs, signatures, or final approval are supplied by this
scope record.
