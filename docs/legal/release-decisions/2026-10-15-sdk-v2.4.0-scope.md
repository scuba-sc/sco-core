# SDK 2.4.0 distribution scope

- Decision: **Recorded.** Keep the five SDK 2.3.0 profiles for SDK 2.4.0, add the new sources and
  tests listed below to the profiles named, and move the game pack and game-sc overlay to the
  patch coordinate 0.6.1 (decisions 1 to 3 below). Decisions 4 to 7 remain open. Published download instructions stay
  at sdk-v2.3.0 until 2.4.0 is signed and published.
- Decided by: scubamount (maintainer)
- Date: 2026-10-15
- Applies to: sdk-v2.4.0 preparation only
- Reviewed source: none; the candidate branch has not been reviewed by the maintainer
- Counsel review: not recorded

The maintainer delegated this release on 2026-10-15 ("publish it all", SDK 2.4.0 included); this
record is the scope that delegation covers. **This record does not itself dispatch a candidate,
create an approval record, sign, tag or publish.** Those steps, and the site publication that
follows them, are separate. The [SDK 2.3.0 scope decision](2026-10-15-sdk-v2.3.0-scope.md) still
applies to 2.3.0 bytes only.

## Coordinates

SDK 2.4.0 for `core`, `legacy`, `core-source` and `host-source-sc`; frozen plugin ABI 1.1
unchanged (`include/sco_api.h` and `tests/abi_v1.c` byte-identical to 2.3.0); game pack and
game-sc overlay 0.6.1 (was 0.6.0). The candidate branch adds production engine backends and the
`teleport.relocation` row behind the existing `game.relocation` 1.0 and `game.quantum` tables and
adds or grows no game service table (no public `sc_*.h` header changes). The
[game-pack policy](../../game-pack.md) says "a release that adds or grows a game service raises the
minor", so the minor stays; the overlay's bytes change, so the patch moves (decision 3). The profile list is
unchanged: `core`, `game-sc`, `legacy`, `core-source`, `host-source-sc`.

`SCO_GAME_PACK_VERSION`, the release notes' scope block and the catalogue test pin say 0.6.1;
decisions 2 and 3 below record it.

## Decisions

1. **Scope and profiles: recorded 2026-10-15.** The five 2.3.0 profiles, unchanged, with the
   profile assignments above. No reviewed source commit is recorded.
2. **Game pack version: recorded 2026-10-15.** No minor raise, under the game-pack policy quoted
   above.
3. **Overlay file name: recorded 2026-10-15.** Patch coordinate 0.6.1 for the game pack and the
   game-sc overlay (`sco-sdk-game-sc-0.6.1.zip`). The 2.4.0 overlay's bytes differ from the 2.3.0
   asset (its documentation changes and its compatibility descriptor binds the 2.4.0 core archive
   SHA-256), and each overlay keeps a file name of its own, as in 2.2.0 and 2.3.0.
4. **Candidate dispatch:** whether and when to dispatch `release-candidate.yml` with
   `tag: sdk-v2.4.0` on the merged `main` commit. Nothing in this record dispatches it.
5. **Evidence accepted for the candidate:** Linux and native Windows builds of the merged branch
   not run locally, the Windows-only adapters `relocation_engine.cpp` and `quantum_engine.cpp`
   not compiled here, nothing run in the game. Hosted CI on the merged `main` commit is the first
   evidence for those.
6. **Changelog section heading:** the preparation branch dates the section
   `## sdk-v2.4.0 (2026-10-15)`, the preparation date. If publication happens on another day, the
   heading's date is the maintainer's to change before the tag.
7. **Getting started at publication:** `docs/getting-started.md` keeps the published 2.3.0
   download and build commands under "Previous release" subheadings, so the docs site never
   shows downloads for an unpublished tag. When 2.4.0 is published, those commands move to 2.4.0
   as release procedure step 1 requires.
