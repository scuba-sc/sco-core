# SDK 2.2.0 distribution scope

- Decision: **Recorded.** Keep `game.hangar` 1.0, `game.reputation` 1.0 and `game.world` 1.1 in
  sdk-v2.2.0, with the game-sc overlay bumped from 0.4.0 to 0.5.0. Keep the five SDK 2.1.0
  profiles for SDK 2.2.0, with the new headers and tools added to the profiles listed below, as
  the draft proposed. Published download instructions stay at sdk-v2.1.0 until 2.2.0 is signed
  and published.
- Decided by: scubamount (maintainer)
- Date: 2026-10-14
- Applies to: sdk-v2.2.0 preparation only
- Reviewed source: not recorded; this decision names no reviewed source commit
- Counsel review: not recorded

**This record does not itself dispatch a candidate, create an approval record, sign, tag or
publish.** Those steps, and the site publication that follows them, remain the maintainer's.
Final candidate bytes still require a fresh schema-v2 approval signed by the maintainer, as in
the [release procedure](../release-checklist.md#releasing). The
[SDK 2.1.0 decisions](2026-10-13-sdk-v2.1.0-host-source.md) still apply to 2.1.0 bytes only.

## Coordinates

SDK 2.2.0 for `core`, `legacy`, `core-source` and `host-source-sc`; frozen plugin ABI 1.1
unchanged; game pack and game-sc overlay 0.5.0 (was 0.4.0), because the candidate keeps the game
tables below, under the additive-service minor rule in [game-pack policy](../../game-pack.md).
The profile list is unchanged: `core`, `game-sc`, `legacy`, `core-source`, `host-source-sc`.

## Decided items and items still open

1. **Profile assignments: decided.** Approved as proposed above. No reviewed source commit is
   recorded in this decision.
2. **Game tables and scaffolder: decided.** Both stay in the candidate; the game pack is 0.5.0
   in `SCO_GAME_PACK_VERSION`, the release notes' scope block and the game-sc overlay name.
3. **game-sc overlay identity: decided by 2.** The overlay rebuilt over the 2.2.0 core ships as
   `sco-sdk-game-sc-0.5.0.zip`, so it never shares a file name with the published
   `sco-sdk-game-sc-0.4.0.zip`.
4. **Evidence accepted for the candidate: not recorded here.** Still the maintainer's, at
   candidate approval: C# builder not compiled locally, Linux and native
   Windows builds of the merged branch not run locally, Windows game-pack adapters for the new
   game tables not built, the scaffolder test not in CI, nothing run in the game. Hosted CI on
   the merged `main` commit is the first evidence for those.
5. **Native-index fields: not recorded here.** Confirm whether the landed index's `hash` and `source` fields fall
   within the [native-index decision](2026-10-14-native-index.md), before the docs site is
   deployed from a commit that contains the index.
6. **Getting started at publication: decided.** Published download instructions stay at
   sdk-v2.1.0 until 2.2.0 is signed and published. `docs/getting-started.md` keeps the published 2.1.0
   download and build commands under "Previous release" subheadings, so the docs site never
   shows downloads for an unpublished tag. When 2.2.0 is published, those commands move to
   2.2.0 (and to game-sc 0.5.0) as release procedure step 1 requires.
