**This draft needs the maintainer's approval before any SDK 2.2.0 candidate is dispatched.** It
authorizes no candidate run, approval record, signature, tag, release or site publication. Until

## Proposed coordinates

SDK 2.2.0 for `core`, `legacy`, `core-source` and `host-source-sc`; frozen plugin ABI 1.1
unchanged; game pack 0.5.0 if the candidate keeps the game tables below, which have landed, under
the additive-service minor rule in [game-pack policy](../../game-pack.md), otherwise 0.4.0.
The profile list is unchanged: `core`, `game-sc`, `legacy`, `core-source`, `host-source-sc`.

## Decisions the maintainer needs to make

1. **Approve or change the profile assignments above** for the landed items, and record the
   reviewed source commit.
2. **Game tables and scaffolder:** both have landed on the candidate branch. Approve the candidate
   with them (the game pack then becomes 0.5.0, in `SCO_GAME_PACK_VERSION`, the release notes'
   scope block and the game-sc overlay name), or have them reverted from the candidate branch
   before any candidate run.
3. **game-sc overlay identity:** the overlay binds the exact core archive digest, so an overlay
   rebuilt over the 2.2.0 core differs in bytes from the published `sco-sdk-game-sc-0.4.0.zip`
   while keeping the same file name. Options: publish a new game-pack coordinate even without
   service changes, or ship 2.2.0 without a new game-sc overlay. Neither is decided here.
4. **Evidence accepted for the candidate:** C# builder not compiled locally, Linux and native
   Windows builds of the merged branch not run locally, Windows game-pack adapters for the new
   game tables not built, the scaffolder test not in CI, nothing run in the game. Hosted CI on
   the merged `main` commit is the first evidence for those.
5. **Native-index fields:** confirm whether the landed index's `hash` and `source` fields fall
   within the [native-index decision](2026-10-14-native-index.md), before the docs site is
   deployed from a commit that contains the index.
6. **Getting started at publication:** `docs/getting-started.md` keeps the published 2.1.0
   download and build commands under "Previous release" subheadings, so the docs site never
   shows downloads for an unpublished tag. When 2.2.0 is published, those commands move to
   2.2.0 (and to the game-sc coordinate decided in 2) as release procedure step 1 requires.
