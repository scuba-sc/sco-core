# SDK 2.3.0 distribution scope (DRAFT)

- Decision: **DRAFT, pending the maintainer.** Proposed: keep the five SDK 2.2.0 profiles for
  SDK 2.3.0, add the new headers and sources listed below to the profiles named, and move the
  game pack and game-sc overlay from 0.5.0 to 0.6.0
- Decided by: nobody yet; prepared for the maintainer on 2026-10-15
- Date: not decided
- Applies to: sdk-v2.3.0 preparation only
- Reviewed source: none; the candidate branch has not been reviewed by the maintainer
- Counsel review: not recorded

**This draft needs the maintainer's approval before any SDK 2.3.0 candidate is dispatched.** It
authorizes no candidate run, approval record, signature, tag, release or site publication. Until
the maintainer records a decision here, the [SDK 2.2.0 scope decision](2026-10-14-sdk-v2.2.0-scope.md)
describes the only recorded scope, and it applies to 2.2.0 bytes only.

## Proposed coordinates

SDK 2.3.0 for `core`, `legacy`, `core-source` and `host-source-sc`; frozen plugin ABI 1.1
unchanged (`include/sco_api.h` and `tests/abi_v1.c` byte-identical to 2.2.0); game pack and
game-sc overlay 0.6.0 (was 0.5.0), because the candidate branch adds `game.asop` 1.0 and
`game.contracts` 1.0 and grows `game.loadout` to 1.1, under the additive-service minor rule in
[game-pack policy](../../game-pack.md). The profile list is unchanged: `core`, `game-sc`,
`legacy`, `core-source`, `host-source-sc`.

The preparation branch already writes 0.6.0 into `SCO_GAME_PACK_VERSION`, the release notes'
scope block and the catalogue test pin, so the documentation gate can run; that is a proposal for
decision 2 below, not a decision.

## Decisions the maintainer needs to make

1. **Approve or change the scope and profiles above**: the five 2.2.0 profiles, unchanged, and the
   profile assignments of the landed items; record the reviewed source commit.
2. **Game pack version:** approve 0.6.0 for the game pack and the game-sc overlay
   (`SCO_GAME_PACK_VERSION`, the release notes' scope block, `sco-sdk-game-sc-0.6.0.zip`), or have
   the new and grown game tables reverted from the candidate branch and the coordinate returned
   to 0.5.0 before any candidate run.
3. **Candidate dispatch authorization:** whether and when to dispatch `release-candidate.yml` with
   `tag: sdk-v2.3.0` on the merged `main` commit. Nothing in this record dispatches it.
4. **Evidence accepted for the candidate:** Linux and native Windows builds of the merged branch
   not run locally, Windows game-pack adapters for `game.asop`, `game.contracts` and
   `Scope::AllFiles` not built, GPU rendering of surfaces not exercised, nothing run in the game.
   Hosted CI on the merged `main` commit is the first evidence for those.
5. **Changelog section heading:** the preparation branch dates the section
   `## sdk-v2.3.0 (2026-10-15)`, the preparation date. If publication happens on another day, the
   heading's date is the maintainer's to change before the tag.
6. **Getting started at publication:** `docs/getting-started.md` keeps the published 2.2.0
   download and build commands under "Previous release" subheadings, so the docs site never
   shows downloads for an unpublished tag. When 2.3.0 is published, those commands move to 2.3.0
   (and to the game-sc coordinate decided in 2) as release procedure step 1 requires.
