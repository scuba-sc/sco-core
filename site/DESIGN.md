# sco-core docs site design contract

This site has no brand of its own. It is the stock Astro Starlight 0.42.6 theme, and
every visual value in `src/styles/portal.css` is either a Starlight token
(`node_modules/@astrojs/starlight/dist/style/props.css`) or a `--sco-*` alias defined
once in that file. New UI extends this contract first, then uses it.

## 1. Source of truth

- Starlight's built-in light and dark themes (`data-theme` on `:root`), the system
  font stacks and the Expressive Code blocks (which supply the copy button).
- No web fonts, no remote assets, no client scripts beyond Starlight's own.
- Content is generated by `scripts/gen.py`; markup classes below are emitted there.

## 2. Colour

| Role | Token |
| --- | --- |
| Surface border | `--sl-color-gray-5` |
| Raised surface | `--sl-color-gray-6` (dark), `--sl-color-gray-7` (light) via `--sco-surface` |
| Heading / strong text | `--sl-color-white` |
| Body text | `--sl-color-text` |
| Muted text | `--sl-color-gray-3` |
| Links | `--sl-color-text-accent` |
| Published status | green ramp: background `--sl-color-green-low`, text `--sl-color-green-high`, border `--sl-color-green` |
| Preview status | orange ramp, same roles; matches the caution aside |

Status is never colour-only: every status chip carries its text label.

## 3. Typography

Starlight scale only: `--sl-text-lg` card titles, `--sl-text-base` body,
`--sl-text-sm` facts and code, `--sl-text-xs` chips. `--sl-line-height-headings`
for titles. Monospace is `--__sl-font-mono` for archive names, versions and SHAs.

## 4. Spacing and radii

`--sco-space-1` 0.25rem, `--sco-space-2` 0.5rem, `--sco-space-3` 0.75rem,
`--sco-space-4` 1rem, `--sco-space-5` 1.5rem (Starlight's own rem steps).
`--sco-radius-sm` 0.25rem (badge), `--sco-radius-md` 0.5rem (link card).

## 5. Primitives

- **Track panel** (`.sco-track`): bordered raised surface; status chip, title, fact list, note.
- **Status chip** (`.sco-status--published`, `.sco-status--preview`).
- **Fact list** (`.sco-facts`): `<dl>` of label/value pairs, values monospace.
- **Profile card** (`.sco-profile`): `<li>` with `<h3>` name, archive, version pill,
  one-line purpose, relation line and two text links (guide, verify).
- **Version pill** (`.sco-pill`): neutral bordered monospace chip.
- Code blocks are plain Markdown fences so Expressive Code renders the copy button.

## 6. Motion

None. Cards and panels are not interactive; only their links are. No hover effects
beyond the link underline Starlight already uses.

## 7. Responsive

One column below 50rem (Starlight's CardGrid breakpoint); two-column tracks and
profile grid at 50rem and above. Long SHAs and archive names wrap
(`overflow-wrap: anywhere`) instead of scrolling horizontally.

## 8. Accessibility constraints and accepted debt

- Semantic structure: `<section aria-labelledby>` per track, `<ul>`/`<li>` cards,
  `<dl>` facts, real headings, real links (no click handlers).
- Focus: `:focus-visible` outline in `--sl-color-text-accent` on every link.
- Contrast: chip text is the `-high` ramp on the `-low` ramp with a mid-tone border.
  Starlight inverts those ramps per theme, so one rule serves light and dark, as its
  asides do.
- Accepted debt: the version header is static HTML inside Markdown, so it does not
  use Starlight's MDX `<Card>` components (the generated home page stays `.md`
  because catalogue prose is not MDX-safe).
